## Why

RM7 established, for one table, that persisted unit-bearing values are stored in the unit they are
displayed in and named with a unit suffix. That decision is currently recorded only inside RM7 —
which means the next agent to add a column to any *other* table has nothing to follow, and the
existing repo-wide convention in `ai/go-conventions.md:44-47` still mandates the opposite pattern
(a read-time `<Field>Km()` companion for every miles field).

A rule that lives in one roadmap is a rule that gets re-derived, re-litigated, or silently broken.
This change promotes it to a platform convention in the docs an agent already loads every session.

**The audit that motivated this change found the schema is already almost entirely compliant.**
That finding is itself the deliverable — it is why this change ships zero migrations.

| Table | Owner | Unit-bearing columns | Verdict |
|---|---|---|---|
| `accounts` | `account` | none | compliant — nothing to do |
| `tesla_tokens` | `account` | none | compliant — nothing to do |
| `vehicles` | `account` | none | compliant — nothing to do |
| `poll_attempts` | `telemetry` | none | compliant — nothing to do |
| `manual_charge_entries` | `manualcharge` | `energy_added_kwh`, `start_battery_pct`, `end_battery_pct` | compliant; `price` is an exempt monetary amount |
| `supercharger_sessions` | `telemetry` | `energy_kwh` | compliant; `total_cost` is an exempt monetary amount |
| `vehicle_snapshots` | `telemetry` | 15 columns | **non-compliant — remediated by RM7, not here** |

No column outside `vehicle_snapshots` stores miles, bar, or Fahrenheit. There is nothing left to
convert once RM7 lands.

## What Changes

- **Add a new `unit-of-measure` capability spec** — the single normative source for the platform's
  unit rules: kilometres for distance, degrees Celsius for temperature, PSI for pressure; every
  persisted unit-bearing column and domain field carries a unit suffix; conversion happens once on
  write and never on read; vendor adapter DTOs are the explicit exception.
- **Rewrite `ai/go-conventions.md:44-47`** — the "Miles → km conversion is mandatory" bullet
  currently requires the read-time companion pattern on *every* miles field. Re-scope it to apply
  to adapter DTOs only, and add the persisted-type rule beside it.
- **Add a naming rule to `ai/go-conventions.md` §Persistence** — unit-suffixed column names, so
  the rule sits where an agent designing a migration is already reading.
- **Update the `CLAUDE.md` non-negotiables bullet** to match, since it is loaded on every request
  and currently states the superseded rule.
- **Add the rule to four module `AGENTS.md` files**: `account`, `manualcharge`, `telemetry` (the
  three that own tables) and `tesla` (the deliberate exception — it mirrors API-native miles/bar).
  `battery` and `gateway` are skipped: they own no schema and persist nothing, so the rule is
  inert there and four copies are cheaper to keep honest than six.
- **Document the monetary-amount exemption**: a money column's unit is dynamic, so it takes no
  suffix and MUST be paired with a `currency` column. This is what makes `price` and `total_cost`
  compliant rather than outstanding debt.
- **Remove tasks 6.2 and 6.3 from `telemetry-store-display-units`** (RM7 tier 2), which currently
  claim ownership of the same `ai/go-conventions.md` and `CLAUDE.md` lines. RM7 tier 2 keeps only
  its module-local `internal/telemetry/AGENTS.md` edit.

**Zero migrations. Zero schema objects. No Go code changes.**

## Capabilities

### New Capabilities

- `unit-of-measure`: the platform-wide contract for units in persisted data and domain types —
  which units the project standardises on, how columns and fields are named, where conversion is
  allowed to happen, and which categories are exempt.

### Modified Capabilities

None. No existing capability's runtime behavior changes — this change adds a cross-cutting
contract and updates the documents that carry it.

## Why this is a single change and not a roadmap

`openspec/config.yaml:32` turns a **multi-module** change into a roadmap, and the change-naming
rule reserves the `platform-` prefix for cross-cutting work. This change edits four module
`AGENTS.md` files but changes **no module's code, schema, generated package, or public surface** —
there is nothing to implement per module and no tier can depend on another. Treating a docs-only
convention as four sequenced tiers would be ceremony with no isolation benefit, and would leave
`platform-` with no case it could ever apply to.

## Ordering relative to RM7

The doc edits here have **no hard apply-order dependency** — they can land before, during, or
after RM7. The `unit-of-measure` spec's compliance scenarios, however, are only fully true once
RM7 tier 4 lands, because `vehicle_snapshots` is the one table still storing miles and bar. This
change should therefore be **archived after RM7 completes**, so the merged spec in
`openspec/specs/` never describes a state the code has not reached. Task 5.3 covers this.
