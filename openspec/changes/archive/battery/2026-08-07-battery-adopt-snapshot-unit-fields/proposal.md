# battery-adopt-snapshot-unit-fields

> **Roadmap:** `RM7-store-display-units`, **tier 3 of 4**
> (`depends_on`: `telemetry-store-display-units`).
> **Generated by skill:** `opsx:propose`.
> **Originating user prompt:** *"The vision of this project is to be faster in read, slow in
> writes. So, if we are doing data transformations for unit of measures when reading them...
> that's not good. right? ... No conversions should be done when reading data."*

## Why

RM7 tier 2 moves unit conversion to the telemetry write path: `telemetry.Snapshot.Odometer`
(miles) becomes `Snapshot.OdometerKm` (kilometres, already converted), and the `OdometerKm()`
companion method is deleted — the new field name collides with it, so it cannot survive.

`internal/battery` calls that method four times (`derive.go:32` twice, `:54-55` once each). After
tier 2 the module does not compile. This tier adopts the new field so it does, and so the battery
capability stops paying a conversion it no longer needs: `deriveEfficiency` currently multiplies by
`1.609344` four times per derivation to recover a number telemetry will now hand it directly.

## What Changes

- Replace the four `OdometerKm()` method calls in `deriveEfficiency` with reads of the
  `OdometerKm` field.
- No change to the efficiency formula, the window semantics, the `Efficiency` result type, the
  `ok=false` conditions, or the account-scoping behavior. `FromKm`/`ToKm` keep their names and
  meanings — they were already kilometres.
- Update `internal/battery/AGENTS.md:48-50`, which documents `FromKm`/`ToKm` as "derived from
  `telemetry.Snapshot.OdometerKm()`" — a method that no longer exists.

**Not breaking for callers.** The battery module's own public surface (`Reader`, `Efficiency`,
`WhPerKm`, `FromKm`, `ToKm`, `BatteryDeltaPct`, `Approximate`) is unchanged, so nothing downstream
of `internal/battery` is affected by this tier.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `battery`: *Recent Energy-Per-Kilometre Derivation* gains an explicit statement that the
  capability consumes the kilometre values the telemetry port already provides and performs no
  unit conversion of its own. The derived value and every existing condition are unchanged — this
  pins down where the kilometres come from, which is the behavioral contract RM7 establishes.

## Impact

**Code**
- `internal/battery/derive.go:32,54-55` — four call sites become field reads.
- `internal/battery/derive_test.go` — `telemetry.Snapshot` literals in the test fixtures use the
  renamed field, and their odometer values now mean kilometres rather than miles.
- `internal/battery/reader_test.go` — same, wherever it builds snapshot fixtures.

**Docs**
- `internal/battery/AGENTS.md:48-50`.

**No impact on:** the database (this module owns none), the `Reader`/`Efficiency` public surface,
`internal/gateway` (RM7 tier 4 handles its own call sites), or any other module.
