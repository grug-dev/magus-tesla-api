# telemetry-store-display-units

> **Roadmap:** `RM7-store-display-units`, **tier 2 of 4**
> (`depends_on`: `tesla-add-tpms-psi-companions`).
> **Generated by skill:** `opsx:propose`.
> **Originating user prompt:** *"The vision of this project is to be faster in read, slow in
> writes. So, if we are doing data transformations for unit of measures when reading them...
> that's not good. right? So, I'd like to move the logic of those conversions when writting them
> into the vehicle snapshots to have the distance units as `km`, the temperature units as `C` and
> the tire pressure as `Psi`. Also, rename the affected core columns of the vehicles snapshots to
> add a suffix with the unit of measure. (e.g. XXX_km, XXX_psi, etc). No conversions should be
> done when reading data. (Thousand separator is something on the UI scope, that's good.. but the
> value should be without it)"*

## Why

`vehicle_snapshots` stores Tesla Fleet API values API-native — distance and range in **miles**,
tire pressure in **bar** — and every consumer converts on read. That inverts the project's stated
performance profile (`CLAUDE.md` → *Performance-Profile: read-heavy — read performance is mandatory
over write performance; writes are mostly done by pollers at midnight, so denormalizing, indexing
aggressively, and precomputing for reads is acceptable*):

| Conversion site | Cost |
|---|---|
| `internal/telemetry/telemetry.go:110-155` — 6 companion methods | the source of all of the below |
| `internal/gateway/handlers/handlers.go:311,313,400,405` | per vehicle card, per dashboard render |
| `internal/gateway/handlers/history.go:147,154,196` | **per chart bar, per render** — up to 30 bars × 2 charts |
| `internal/battery/derive.go:32,54-55` | per efficiency derivation |

A snapshot is written **once per vehicle per night** and read on every page load. The multiplication
belongs on the write side.

Two structural problems get fixed with it. The schema hides its units — `odometer`, `inside_temp`
and `charger_power` carry no unit in their names, so the unit is only discoverable by opening a
migration comment. And the conventions in `ai/go-conventions.md:44-47` plus the matching
`CLAUDE.md` non-negotiable currently *mandate* the read-time companion pattern this change reverses,
so they must be re-scoped here rather than silently violated.

## What Changes

- **BREAKING** — `vehicle_snapshots` stores display units: kilometres, Celsius, PSI. A migration
  renames 15 columns to carry their unit as a suffix and converts the 6 whose value changes,
  in place (RM7 Decisions 2–3).
- **BREAKING** — `telemetry.Snapshot`'s fields absorb the suffix (`Odometer` → `OdometerKm`,
  `InsideTemp` → `InsideTempC`, `TpmsPressureFL` → `TpmsPressureFLPSI`, …) and the six read-time
  companion methods at `telemetry.go:110-155` are **deleted**. The rename collides with the method
  names, so deleting them is required for the package to compile, not optional cleanup
  (RM7 Decision 6).
- `snapshotFrom` converts at capture time by calling the `tesla` adapter's companions —
  `data.VehicleState.OdometerKm()`, `data.ChargeState.BatteryRangeKm()`, and the four
  `TpmsPressure*PSI()` methods added in tier 1. No new arithmetic is written here.
- `internal/telemetry` drops both conversion constants (`milesToKm`, `barToPSI`); after this tier
  every unit conversion in the repo lives in `internal/tesla` (RM7 Decision 5).
- Temperature columns are renamed but **not** converted — the Fleet API already reports Celsius.
- `raw_data` is untouched and keeps the original miles/bar payload losslessly, so no information
  is destroyed and any row can be re-derived (RM7 Decision 10).
- `internal/telemetry/AGENTS.md` is corrected here. The platform-wide convention rewrite
  (`ai/go-conventions.md`, root `CLAUDE.md`) is **not** part of this change — it is owned by
  `platform-unit-of-measure-convention`, so one rule has one owner (RM7 Decision 12, amended).

**This tier deliberately leaves the tree not building.** `internal/battery` and `internal/gateway`
call the deleted companions; RM7 tiers 3 and 4 adopt the new fields and restore
`go build ./...` (RM7 Decision 8). This tier's own gate is module-scoped — see `tasks.md` §7.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `telemetry`: three requirements change at the spec level.
  - *Nightly Vehicle Snapshot Capture* — the snapshot is now stored in display units under
    unit-suffixed names, converted at capture, rather than API-native miles/bar.
  - *Latest Snapshot Read Port* — the read port no longer exposes PSI companion methods; the
    pressure fields themselves are PSI. Nil fidelity is unchanged but is now carried by the
    stored nullable column rather than re-derived per call.
  - *Snapshot History Read Port* — its explicit "distance and range fields SHALL be returned in
    miles ... with no kilometre field" clause is exactly inverted.

## Impact

**Database** — `vehicle_snapshots` only. 15 columns renamed, 6 values converted in place, one
backfill `UPDATE`. **No index, constraint, table, or view is added, dropped, or rebuilt**: neither
`vehicle_snapshots_account_tesla_date_unique` `(account_id, tesla_id, captured_date)` nor
`idx_vehicle_snapshots_vehicle_time` `(account_id, tesla_id, captured_at)` references any renamed
column. Triggers the **`database` design gate** (`CLAUDE.md` → Design-Gates) — the migration and
index plan need explicit user confirmation before Apply.

**Code (`internal/telemetry`)**
- `db/migrations/20260806000001_store_display_units_vehicle_snapshots.sql` — new
- `db/query.sql` + regenerated `db/query.sql.go` — the column lists in `InsertVehicleSnapshot`
  (including its `ON CONFLICT ... DO UPDATE SET` block), `ListSnapshotsByVehicle`, and
  `SnapshotsByVehicleSince`; the header comment at `query.sql:20-21` asserts the *opposite* of the
  new rule and must be rewritten
- `telemetry.go` — field renames; delete 6 companions; drop `milesToKm` and `barToPSI`
- `service.go:469-503` (`snapshotFrom`) — convert via the adapter companions
- `mapping.go:104-118` — row→domain field renames
- `AGENTS.md:107-115` — the DTO/units section states the rule being reversed

**Docs — module-local only**
- `internal/telemetry/AGENTS.md:107-115`. The repo-wide convention docs (`ai/go-conventions.md:44-47`
  and the matching `CLAUDE.md` non-negotiable) are owned by `platform-unit-of-measure-convention`
  and are deliberately NOT edited here.

**Downstream, out of scope for this tier** — `internal/battery` (RM7 tier 3) and
`internal/gateway` (RM7 tier 4).

**No impact on:** `supercharger_sessions`, `poll_attempts`, `internal/manualcharge`, the Fleet API
surface, HTTP routes, or the `tesla-exploration` capability.
