# RM8-gateway-history-date-range

Switch `GET /ui/dashboard/history` from the opaque `?days=N` count param to a bounded calendar-day window `?start=YYYY-MM-DD&end=YYYY-MM-DD` (`end` inclusive, default 6-day window, 400 on malformed / `end<start` / `end>today` / window>90d), fetched via `telemetry.Reader.SnapshotsByVehicleBetween` with a 1-day lookback for the first odometer delta, and bucket both charts to a **fixed `[start..end]` date axis** — one bar per calendar day, identical MM-DD labels on both charts, missing days = empty labeled slots — fixing the MAG-7 odometer/battery axis offset. Keep the 6/14/30 preset selector but server-render absolute `start`/`end` hrefs, remove the dashboard page Refresh button, and record the start/end HTTP convention in `internal/gateway/AGENTS.md` (canonical) + a one-line pointer in `ai/go-conventions.md`. This is tier 2 of the `RM8-history-date-range` roadmap (Linear MAG-7); tier 1 (`RM8-telemetry-between-range-port`) already added `SnapshotsByVehicleBetween`. Breaking change to the gateway HTTP API (`?days=N` → `?start=&end=`).
