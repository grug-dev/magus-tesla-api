# RM4 — Charge form: required location + vehicle auto-select

> **Generated by skill:** `kkpa-dev-harness-pipeline` (leader/roadmap mode)
> **Originating user prompt:** *"I want some improvements on the manualcharge module. Are you
> ready to generate the proposal? Are you reading the openspec spec for that module to implement
> this change?"* — refined via the pipeline interview to: (1) make `location_kind` a **required**
> field on the manual charge form, front-end **and** back-end; (2) **auto-select the vehicle** in
> the create form — if the tenant has one vehicle, auto-select it and disable the control; if
> more than one, auto-select the first vehicle whose Tesla `access_type` is `OWNER`.
> **Date:** 2026-07-19

## Intention

When all tiers land, the manual charge create form always captures a location (`HOME`/`WORK`/
`OTHER`) — no more untagged entries — and pre-selects the right vehicle automatically, so the
common single-vehicle owner never touches the vehicle picker and multi-vehicle owners default to
the car they own.

## Scope note — why this is a roadmap, not one change

The two asks span **four modules** and require plumbing Tesla's `access_type` (captured nowhere
today) from the adapter through persistence to the UI. Per `openspec/config.yaml` (proposal rule:
multi-module ⇒ roadmap), each module gets its own module-prefixed tier change on a single shared
`ft/RM4-…` branch.

## Decisions (binding — captured in the pre-proposal `grill-me` interview)

These were confirmed by the user and are authoritative for every tier's design/spec/tasks.

1. **`location_kind` → `NOT NULL`.** Forward migration does a defensive
   `UPDATE … SET location_kind = 'OTHER' WHERE location_kind IS NULL` (a no-op after the DB wipe,
   but keeps the migration safe against any non-empty environment) then
   `ALTER COLUMN location_kind SET NOT NULL`. **No column `DEFAULT`** — the app always sends a
   value; a DEFAULT would mask a missing field instead of failing.
2. **`location_kind` required on create AND edit.** Enforced in the shared gateway
   `parseChargeForm` (rejects missing) and by the DB `NOT NULL`. The manualcharge service also
   validates it. The domain field **stays `*string`** (boundary-nil-safe) but is validated
   non-nil/non-empty on Create/Update — this keeps the repo compiling after the manualcharge tier,
   before the gateway tier lands.
3. **`access_type` column.** `vehicles.access_type TEXT` **nullable**, guarded by
   `CHECK (access_type IS NULL OR access_type IN ('OWNER','DRIVER'))`. **No index** (read only as
   part of the already-fetched per-account vehicle list; never a filter predicate). Domain fields
   `Vehicle.AccessType` / `OwnedVehicle.AccessType` / `SeedVehicle.AccessType` are `*string`.
4. **No `access_type` backfill mechanism.** The user is wiping all DB table data, so every vehicle
   is freshly seeded *after* this ships and the first seed captures `access_type` directly. No
   `SeedVehicles` `ON CONFLICT` change, no relaxing the "never call Tesla again" invariant, no
   re-seed trigger. **Operational caveat:** the wipe must happen *after* the tesla + account tiers
   deploy; a mis-ordered wipe degrades gracefully (NULL `access_type` → first-in-list fallback).
5. **Auto-select is create-form only** (the edit row already has a bound vehicle). Rule: single
   vehicle → select **and `disabled`** + a hidden `<input name="vehicle">` so the value still
   POSTs; else first `OWNER`; else **first in list**. Never left unselected.
