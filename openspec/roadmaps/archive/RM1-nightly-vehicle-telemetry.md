# Roadmap — RM1-nightly-vehicle-telemetry ✅ complete

**Intention:** every connected user's vehicles get one anchor telemetry snapshot per
night (03:30 local, waking the car if needed), stored immutably by the platform. Users
never trigger Tesla API calls — dashboards read only what the server already collected.

Generated by the **kkpa-dev-harness-pipeline** (leader session, 2026-07-10) from the
user prompt:

> Build the poller: a scheduled runner (cmd/poller) that periodically fetches vehicle
> data for all connected users and appends snapshots to the database — the foundation
> for all historical data features (daily digest, battery health log, charge session
> detection)

## Decisions (grill-me interview, 2026-07-10 — binding for every tier's proposal)

- **Scope:** ALL connected users. Vehicles enumerated from account's registry (new port
  method); access token via existing `AccessTokenFor(accountID)`.
- **Cadence:** daily at **03:30 local**, via an **in-app daemon scheduler** (`cmd/poller`
  long-running, schedule ships with the app — no OS cron). Time/TZ configurable.
- **Wake policy:** wake sleeping vehicles with a bounded timeout (~90 s), then let them
  sleep. Sanctioned by `AGENTS.md` §"Data Access Model" (added 2026-07-10).
- **Data Access Model:** users NEVER hit Tesla APIs on demand — the only user-initiated
  call is the vehicle list at first connect. All collection is background-only;
  dashboards read stored data exclusively.
- **Snapshot content:** full raw `vehicle_data` JSONB **plus** extracted typed columns
  (battery level, rated range, charging state, charge limit, odometer, inside/outside
  temp, locked, sentry mode, car version, lat/lng). Units stay API-native (miles) with
  `Km()`/`Kmh()` companions on Go DTOs per the non-negotiable convention.
- **Failure policy:** per-vehicle isolation (one failure never aborts the run); every
  attempt recorded in a `poll_attempts` table with a reason (`asleep-timeout`,
  `unauthorized`, `api-error`, …) — doubling as data for future availability/sleep
  metrics; expired/revoked tokens flag the account's connection as broken; one bounded
  retry per vehicle per run.
- **Descoped:** charge-session detection and adaptive polling → Future work below.
- **Tier-4 scope (user, 2026-07-11):** the dashboard must **surface the nightly snapshot
  data** (battery %, range, charge state, last-updated), not merely read the registry —
  chosen over a compliance-only tightening (near no-op, since the dashboard already reads
  the registry and only seeds Tesla at first connect). This makes tier 4 **multi-module**:
  `telemetry` first gains a public snapshot **read** port, then `gateway` displays it.
  Original single-tier `gateway-read-stored-vehicles` split into tiers 4 (telemetry read
  port) + 5 (gateway display).
